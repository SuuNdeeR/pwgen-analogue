## 1. Назначение продукта

**Password Generator** — консольная утилита для генерации случайных паролей.
Программа позволяет гибко управлять параметрами генерации: длиной, набором
допустимых символов, количеством паролей.

Продукт является упрощённым аналогом утилиты `pwgen` для Unix-систем.

---

## 2. Функциональность

- Генерация одного или нескольких паролей заданной длины.
- Управление набором символов через флаги командной строки.
- Два режима генерации: стандартный (равномерный случайный выбор из алфавита через `rand()`) и безопасный (через `/dev/urandom` при флаге `-s`).
- Режим вывода: по одному на строку.
- Вывод справки и версии программы.

---

## 3. Интерфейс приложения

Консольная утилита (CLI). Принимает аргументы командной строки, выводит результат
в `stdout` и завершает работу. Каждый пароль выводится на отдельной строке.

---

## 4. Аргументы командной строки

```
./bin/pwgen [ОПЦИИ] [ДЛИНА [КОЛИЧЕСТВО]]
```

**Позиционные аргументы:**

| Аргумент     | По умолчанию | Диапазон      | Описание                        |
|--------------|--------------|---------------|---------------------------------|
| `ДЛИНА`      | 8            | 4 – 256       | Длина генерируемого пароля      |
| `КОЛИЧЕСТВО` | 1            | 1 – 10000     | Количество генерируемых паролей |

**Флаги:**

| Короткий | Длинный           | Описание                                               |
|----------|-------------------|--------------------------------------------------------|
| `-c`     | `--capitalize`    | Включить заглавные буквы                               |
| `-A`     | `--no-capitalize` | Не включать заглавные буквы                            |
| `-n`     | `--numerals`      | Включить цифры                                         |
| `-0`     | `--no-numerals`   | Не включать цифры                                      |
| `-y`     | `--symbols`       | Включить специальные символы (`!@#$%^&*...`)           |
| `-s`     | `--secure`        | Генерация через `/dev/urandom`                         |
| `-B`     | `--no-ambiguous`  | Исключить неоднозначные символы (`l`,`1`,`O`,`0`,`I`)  |
| `-h`     | `--help`          | Вывод справки                                          |
|          | `--version`       | Вывод версии программы                                 |

**По умолчанию** включены только строчные латинские буквы (`a-z`).

**Примечание по валидации:**  
Если `ДЛИНА` < 4 или > 256, либо `КОЛИЧЕСТВО` < 1 или > 10000 — программа
завершается с кодом `1` и сообщением об ошибке в `stderr`.

**Примечание по обработке конфликтующих флагов:**  
Если указаны одновременно противоречащие флаги (-c и -A, -n и -0), последний указанный в командной строке имеет приоритет. Например, ./bin/pwgen -c -A равносилен ./bin/pwgen -A (заглавные буквы отключены).

**Примеры:**

```bash
# 1 пароль длиной 8 символов
./bin/pwgen

# 5 паролей длиной 16 символов с заглавными и цифрами
./bin/pwgen -cn 16 5

# Безопасный пароль из 20 символов со спецсимволами
./bin/pwgen -sy 20

# Пароль без неоднозначных символов
./bin/pwgen -B 12

# Использование в скрипте
PASSWORD=$(./bin/pwgen -s 24)
```

## 5. Коды возврата программы

**Программа возвращает один из следующих кодов завершения:**

| Код  | Значение                                                                                       |
|------|------------------------------------------------------------------------------------------------|
| `0`  | Успешное выполнение (пароли сгенерированы и выведены).                                         |
| `1`  | Ошибка в аргументах командной строки (неверный флаг, недопустимое значение длины/количества).  |
| `2`  | Ошибка выполнения (например, не удалось открыть `/dev/urandom` при флаге `-s`).                |

## 7. Распределение задач

### Участник 1 — модуль `args` + `main.c`

**Файлы:** `src/args.c`, `include/args.h`, `src/main.c`, `tests/test_args.c`

**`args.c`** — разбор аргументов командной строки (`getopt` / `getopt_long`):
- Короткие (`-c`, `-A`, `-n`, ...) и длинные (`--capitalize`, `--secure`, ...) флаги.
- Позиционные аргументы `ДЛИНА` и `КОЛИЧЕСТВО`.
- Валидация: `ДЛИНА` >= 4, и <= 256, `КОЛИЧЕСТВО` >= 1 и <= 10000. При нарушении — код возврата `1`.
- `--help`, `--version`.

**`main.c`** — точка входа и связующий:
- Инициализирует `PwgenOptions` значениями по умолчанию (set_default_options).
- Вызывает `parse_args()`. По возвращаемому коду:  
   • HELP/VERSION -> вызывает `print_help()/print_version()` -> exit(0).  
   • ERROR -> exit(1) (сообщение уже выведено в stderr).  
   • OK -> переходит к генерации.  
- Один раз вызывает `charset_build()` для формирования алфавита (до цикла).  
   • Если вернул <= 0 -> stderr "Пустой алфавит" -> exit(2).  
- Выделяет буфер под один пароль: `char *pwd = malloc(opts.length + 1)`.
- Цикл count раз:  
   • `generate_password(pwd, opts.length, &opts)`.  
   • `output_print(pwd)`.  
- Освобождает буфер, завершает работу с кодом 0.
- Обрабатывает коды возврата (`0`, `1`, `2`).
- **Не содержит логики генерации самостоятельно**.

```c
/* include/args.h */
typedef struct {
    int  length;
    int  count;
    bool capitalize;
    bool no_capitalize;
    bool numerals;
    bool no_numerals;
    bool symbols;
    bool secure;
    bool no_ambiguous;
} PwgenOptions;
```

**Примечание по структуре:**  
Структура хранит только итоговое состояние. Конфликтующие пары (-c/-A, -n/-0) разрешаются в args.c простым перезаписыванием полей. Дополнительная логика согласования в main.c или charset.c не требуется.

```c
int  parse_args(int argc, char *argv[], PwgenOptions *opts);
void set_default_options(PwgenOptions *opts);
void print_help(void);
void print_version(void);
```

**Задачи (Issues):**
- Разбор коротких флагов (`-c`, `-A`, `-n`, `-0`, `-y`, `-s`, `-B`).
- Разбор длинных флагов (`--capitalize`, `--secure`, ...).
- Разбор позиционных аргументов `ДЛИНА` и `КОЛИЧЕСТВО`.
- Реализация `--help` и `--version`.
- Реализация `main.c` (связывание модулей в пайплайн).
- Валидация входных данных.
- Unit-тесты `test_args.c`: дефолты, корректные/некорректные флаги, конфликт `-c` `-A`, `--help`/`--version`.

### Участник 2 — модули `charset` + `generator`

**Файлы:** `src/charset.c`, `include/charset.h`, `src/generator.c`, `include/generator.h`, `tests/test_charset.c`, `tests/test_generator.c`

**`charset.c`** — сборка алфавита допустимых символов:
- База: `a-z`.
- Добавление `A-Z`, `0-9`, спецсимволов по флагам.
- Исключение неоднозначных (`l`, `1`, `O`, `0`, `I`) при `-B`.

**`generator.c`** — алгоритм генерации пароля:
- **Стандартный режим**: равномерный случайный выбор символа из алфавита через `rand()`.
- **Secure-режим**: равномерный выбор из алфавита через `random_index()` (функция из модуля участника 3).
- `ensure_requirements()` — гарантия хотя бы одного символа из каждого требуемого класса.

```c
/* include/charset.h 
 * Собирает алфавит допустимых символов по флагам из opts.
 * out      — буфер для записи алфавита (null-terminated строка).
 * out_size — размер буфера, включая '\0'.
 * Возвращает: длину алфавита (> 0) или 0 при ошибке (пустой алфавит). */
int charset_build(const PwgenOptions *opts, char *out, size_t out_size);

/* include/generator.h */
int generate_password(char *buf, int length, const PwgenOptions *opts);
```

**Задачи (Issues):**
- Реализация `charset_build` с фильтрами.
- `ensure_requirements` (дозаполнение обязательными символами).
- `generate_password` принимает готовый алфавит и его длину, не вызывает `charset_build` самостоятельно.
- Unit-тесты `test_charset.c`: состав алфавита при разных флагах, фильтрация -B.
- Unit-тесты `test_generator.c`: длина пароля, наличие обязательных классов символов.

### Участник 3 — модули `random` + `output` + инфраструктура

**Файлы:** `src/random.c`, `include/random.h`, `src/output.c`, `include/output.h`, `tests/test_random.c`, `tests/test_output.c`, `tests/test_main.c`, `Makefile`, `.github/workflows/ci.yml`, `.clang-format`, `thirdparty/ctest.h`, `.gitignore`

**`random.c`** — Чтение случайных байт из /dev/urandom для режима `-s`:
- Открытие и чтение `/dev/urandom`.
- `random_index(max)` — выбор числа `[0, max)` через `/dev/urandom` **с защитой от modulo bias (метод отбраковки)**.
- Обработка ошибок (код возврата `2`, если устройство недоступно).

**`output.c`** — вывод результатов:
- Печать одного пароля в `stdout` с переводом строки

**Инфраструктура:**
- `Makefile`: цели `test`, `check-style`, `format`, `coverage`, `clean`.
- GitHub Actions CI: сборка, проверка стиля (`clang-format --dry-run --Werror`), запуск тестов.
- `.clang-format`, `thirdparty/ctest.h`, `.gitignore`, `README.md`.

```c
/* include/random.h */
int  random_init(void);
void random_cleanup(void);
int  random_index(int max);   /* [0, max) */

/* include/output.h 
   Выводит один пароль в stdout с переводом строки */ 
void output_print(const char *password);
```

**Задачи (Issues):**
- Настроить `Makefile` (`make`, `make format`, `make check-style`, `make test`, `make coverage`, `make clean`).
- Реализация `random.c` (чтение /dev/urandom).
- Реализация `output.c`.
- Настроить CI в GitHub Actions (сборка + тесты на каждый push/Pull Request).
- Unit-тесты `test_random.c`: диапазон random_index, ошибка при недоступности /dev/urandom.
- Unit-тесты `test_output.c`: корректность \n, отсутствие мусора в stdout, обработка NULL.

## 8. Тестирование

**Фреймворк:** [ctest] (https://github.com/bvdberg/ctest) — легковесный
unit-testing framework для C. Представляет собой единственный заголовочный 
файл `thirdparty/ctest.h`, который подключается в каждый тестовый модуль.
Точка входа (`main()`) генерируется макросом `CTEST_MAIN` в файле
`tests/test_main.c`.

Тесты пишутся параллельно с реализацией.

| Модуль      | Примеры тест-кейсов                                                                                                                              |
|-------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| `args`      | Дефолтные значения; флаги парсятся верно; конфликт `-c -A` и тому подобные разрешается в пользу последнего; невалидная длина возвращает ошибку.  |
| `generator` | Длина пароля совпадает с запрошенной; при `-c` есть хотя бы одна заглавная буква; при `-B` отсутствуют неоднозначные символы.                    |
| `output`    | Функция вывода отрабатывает без ошибок при передаче одного пароля.                                                                               |
| `charset`   | Состав алфавита при разных флагах; фильтрация -B                                                                                                 |
| `random`    | random_index в диапазоне [0, max); ошибка при недоступности /dev/urandom                                                                         |

## 9. Инфраструктура

**Makefile — минимальный контракт:**
```
make             — сборка bin/pwgen
make check-style — проверка форматирования (не изменяет файлы)
make format      — автоматического применения .clang-format ко всем *.c и *.h.
make test        — сборка и запуск тестов
make coverage    — тесты + отчёт покрытия (минимум 60%)
make clean       — очистка артефактов
```

**Примечание о структуре сборки:**  
Папки `bin/` и `obj/` содержат файлы `.gitkeep`, 
чтобы сохраняться в репозитории Git. Все остальные
файлы внутри этих папок игнорируются через `.gitignore`. При сборке
Makefile кладёт бинарники в `bin/` и объектные файлы в `obj/`.

**CI (GitHub Actions)** — запускается на каждый push и Pull Request в `main`:
1. `make`               — компиляция без ошибок.
2. `make check-style`   — код корректно отформатирован.
3. `make test`          — все тесты проходят.
4. `make coverage`      — отчёт % покрытия.

**Ветки:** `issue-<номер>[-описание]`, например `issue-3-arg-parsing`.  
**Коммиты:** `Issue-N: краткое описание` (например, `Issue-3: add flag parsing`).  
**Слияние:** только через Pull Request, с флагом `--no-ff`.

## 10. Ограничения

- Глобальные переменные запрещены. Глобальные константы — допустимы.
- Абсолютные пути к файлам в коде недопустимы.
- Кодировка исходников — UTF-8, перевод строк — LF.
- Форматирование кода — согласно `.clang-format` из репозитория.
- Все функции, не используемые вне своего .c, должны быть static.
- Не использовать else после return, break, continue.
- Избегать магических чисел (в коде должны быть именованные константы).
- Обязательно указывать имена параметров в объявлениях функций (в .h).
- Для структур, объединений и перечислений обязательно использовать `typedef`.
- Использовать `const` для неизменяемых параметров и переменных.
